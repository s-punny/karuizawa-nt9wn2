## 悩んだ点・捨てた案

- **「仮」マーカーの見せ方**。最初は枠線付きのバッジ（0.5px border + padding）にしたが、
  タイムラインの注記など小さい文字に付くと潰れて「読めない小さな箱」になった。
  枠を捨てて、金の下線＋9px固定の「仮」の文字だけに変更。em指定をやめてpx固定にしたのがポイント。
- **`.tbd` をブロック要素に直接付けた問題**。`<dd class="tbd">` のようにすると
  ハイライトの下線がグリッドのセル幅いっぱいに伸びた。中身を `<span>` で包む方式に統一。
- **`text-transform:uppercase` を日本語混じりのラベルに当てて「新婦FAMILY」になった**。
  英字コード（Route A）と日本語ラベルを別spanに分離して解決。以降、和欧混在のラベルは分ける方針に。
- **Cormorant Garamond の既定がオールドスタイル数字**で、日付の「10」が「IO」に見えた。
  `font-variant-numeric: lining-nums` を body に。時刻表記が多いページなので影響が大きかった。
- **参列者全員に「仮」バッジを付けたらノイズだらけになった**。全員が未確定なら個別に印を付ける意味がない。
  バッジを外して「お名前は仮置きです」の注記1行に置き換え。
- **全体を暗色にするか**で迷った。大人っぽさ＝暗い、と短絡しかけたが、
  表紙と奥付だけ濃色・中面は紙色、という冊子のリズムに落ち着けた。全面暗色は読む文書として重い。
- **前撮り写真がない**という制約。ユーザーから「軽井沢の風景やチャペルの感じなら入れられる」と聞き、
  「写真がなくても成立し、置けば差し替わる」設計にした。
  画像が無ければJSで `<img>` を除去してプレースホルダのまま残す（壊れた画像アイコンを出さない）。
- **公開方法**。GitHub Pages の無料プランは、リポジトリを private にしてもページ自体は公開される。
  このページには両家の氏名・電話・宿泊先・**当日自宅が留守になる日付**が載る。
  パスワード保護のために Cloudflare Pages / Netlify に移す案も出したが、
  検索避け（noindex + robots.txt）＋推測されにくいリポジトリ名（`karuizawa-nt9wn2`）で十分と判断して見送り。
  リポジトリ名から `wedding` `invitation` を排除したのはそのため。
- **地図の実装**。APIキーが要る Maps JavaScript API ではなく、`output=embed` のiframe方式。
  住所が決まったらURLの `q=` を書き換えるだけで済む。色は grayscale + sepia でページの色域に寄せた。
- **「全部やって」に対してどこまでできたか**。gh CLI が未インストール、
  Chrome操作は権限で拒否、トークンを預かるのは方針として不可。
  結果「空リポジトリの作成だけ手動、それ以外は自動」に落として提示した。

## 学び・気づき

- Git Credential Manager に GitHub の資格情報があれば push は非対話で通る。
  `credential.helper` は global が空でも system 側（`C:/Program Files/Git/etc/gitconfig`）に `manager` が入っている。
- GitHub Pages は main に push しただけでは有効化されない。Settings → Pages での設定が必須。
  （`gh-pages` ブランチによる自動有効化を期待したが、今回は発生しなかった）
- `og:image` は絶対URLでないと LINE がサムネイルを取得しない。相対パスだと無言で無視される。
- `noindex` を入れても LINE のリンクプレビューは機能する（クローラが別扱い）。
- ブラウザのプレビューペインが非表示だとページがフレームを composite せず、
  IntersectionObserver が発火せずスクショも撮れない。表示確認の結果が「壊れている」ように見えて紛らわしい。

## 悩んだ点・捨てた案

- **「道のり」を消すと章ごと消えるか問題**。弐の章には道のり（きっぷ）と会場情報（住所・地図）が
  同居していた。章ごと落とすと会場の住所と地図まで消えるため、きっぷだけを外して章を改題した。
- **写真をどこに使うか**。3枚とも 540×400 / 280×200 と小さい。
  全幅の帯（2000px相当）や表紙の背景（100svh）に使うと確実に眠い絵になるので、
  表示サイズが元データを大きく超えない置き方＝本文幅内の組写真に変更した。
  表紙は写真なし（既存のグラデーションのまま）を維持。
- **外観と内観のどちらを大きく使うか**。緑と木立が写っている外観の方が
  「高原の林のなかに、ちいさな教会があります」というキャプションと噛み合うので外観を主役に。
  内観は挙式会場カード側で使い、同じ写真の二度出しを避けた。
- **部屋割りを消したあとの右列**。1枚だけにすると `.duo` が1カラムになり、
  ホテル写真のプレースホルダが幅860pxの巨大な空箱になった。実務的に必要な
  チェックイン・精算の情報をカードにして埋めた。

## 学び・気づき

- 低解像度の写真は「使わない」ではなく「小さく使う」で足りることが多い。
  レイアウト側の表示幅を元データに寄せれば、差し替え前提のまま公開できる。
- `<br>` を `display:none` で畳むときは、ソース上の改行＋インデントが
  そのまま半角スペースとして残る。折り返し位置を変えるだけの `<br>` は行末に詰めて書く。
- Playwright + `/opt/pw-browsers/chromium` でセクション単位のスクショが撮れる。
  `.rv` は IntersectionObserver 待ちなので、撮影前に `classList.add('in')` を流し込むと確実。
